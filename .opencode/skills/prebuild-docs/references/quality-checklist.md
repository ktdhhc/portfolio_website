# 质量检查清单

生成文档体系前，使用本清单做最终检查。

## 分层检查

- [ ] `AGENTS.md` 写的是工作规则，而不是详细项目状态。
- [ ] `CURRENT_STATE.md` 写的是当前事实，而不是历史过程。
- [ ] `FRONTEND_DESIGN.md` 写的是稳定设计约束，而不是实现琐事。
- [ ] `docs/plans/` 存放的是重要方案，而不是随机笔记。

## 降噪检查

- [ ] 没有原样塞入会议纪要。
- [ ] `CURRENT_STATE.md` 内没有 changelog。
- [ ] 没有把已废弃想法写成当前事实。
- [ ] 没有把临时 workaround 升级成默认规则。
- [ ] 没有宣传文案。

## 可用性检查

- [ ] 新 coding agent 可以先读 `AGENTS.md` 和 `CURRENT_STATE.md` 开始工作。
- [ ] 默认阅读路径清楚。
- [ ] 目录和入口文件容易定位。
- [ ] 验证命令明确，或已标记为 `<pending>`。
- [ ] 缺失信息使用占位符，而不是编造。

## CURRENT_STATE 纪律

- [ ] `CURRENT_STATE.md` 不超过 250 行，除非用户明确要求更长。
- [ ] 内容可以覆盖式更新。
- [ ] 只记录会影响实现判断的事实。

## 前端文档纪律

- [ ] UI 气质、布局、组件、状态和交互边界明确。
- [ ] 文档能减少后续设计漂移。
- [ ] 没有为了首版引入过度复杂的组件体系。

## 输出检查

- [ ] 所有必需文件都已生成或完整给出。
- [ ] 可选方案文件不超过 3 个。
- [ ] 输出内容可直接落盘。
- [ ] 没有把 skill 自身的分析过程写进目标项目文档。
