# HEART-Bench 开发笔记

## 理论框架的设计思考

### S-O-R 认知模型的选择

选择 S-O-R（Stimulus-Organism-Response）模型作为理论骨架，是因为它简洁且有足够的解释力：

- **S（Stimulus）**：外界刺激，即记忆 + 情境数据输入给角色。这部分是可测量、可控制的。
- **O（Organism）**：无法直接测量的信息，代表人格、情绪等内在状态。这部分是"黑盒"，我们只能通过 R 来间接推断。
- **R（Response）**：最终外显的具体行动或对话。这是我们能观察到的。

这个模型的好处是：它把"人格"和"记忆"放在了 S 的位置，把"行为"放在了 R 的位置，中间的 O 是我们无法直接测量但需要推断的。这正好对应了评测的核心问题：Agent 能否从 S（记忆 + 人格）推导出符合预期的 R（行为）？

### DIAMONDS 情境理论的降级

DIAMONDS（Duty, Intellect, Adversity, Mating, pOsitivity, Negativity, Deception, Sociality）是一个描述情境特征的八维度理论。最初打算作为核心理论应用——将角色放到各种不同维度分数的情境中，看是否触发符合其情境的行为。

但团队经过工程权衡后决定降级，仅作为衡量测试集情境丰富度的指标引入论文。原因：

1. **工程复杂度**：如果要精确控制每个情境的 DIAMONDS 分数，需要大量的专家标注工作
2. **理论适用性**：DIAMONDS 更适合描述客观情境特征，而我们的评测更关注角色的主观情境感知
3. **成本效益**：降级后仍能展示数据集的情境覆盖度，但大幅降低了构建成本

这个决定虽然降低了理论深度，但提高了工程可行性。

## 数据集构建经验

### 角色和桥段的选择逻辑

数据集的角色来源包括两部分：

**经典角色**（从 personality-database.com 等平台选取）：
- 知名度高，确保普通人能理解
- 人格特点鲜明，有明确的人格标签（MBTI + 大五），便于量化
- 戏剧性强，桥段代表角色的某个鲜明人格特点，能唤起普通人共鸣

**虚构普通人**（完全虚构的现代普通人角色）：
- 没有明确的作品背景，更贴近普通人的生活场景
- 用于测试 Agent 在日常道德困境中的行为决策
- 可以作为对比基准

经典情节桥段的设计思路：

- 每个桥段包含 3-4 个行为分支，每个分支对应不同的人格特质
- 分支 A 通常是"原著向"，即角色在原作中的选择
- 其他分支代表不同的人格倾向，作为干扰项

### 大五人格理论的应用

大五人格（Extraversion, Neuroticism, Agreeableness, Conscientiousness, Openness）是数据集的核心理论之一，用来分析某类人格特征的行为规律：

- **角色设定**：每个角色都用大五人格量化，作为"出厂设置"
- **行为预测**：通过控制人格变量（如高神经质、低宜人性等），可以验证不同类型的人格在不同情境下的认知和行为相关程度
- **评测逻辑**：Ground Truth 基于角色记忆 + 人格数据确定，测试 Agent 能否从记忆中还原出正确的人格倾向

### 长记忆特征

数据集的一个核心特征是"长"——每个角色拥有 100k 以上的记忆量。这个设计的目的是：

- 测试 Agent 在长程互动中的行为一致性，而非短期的问答能力
- 模拟真实的陪伴场景，用户和 Agent 会有大量的历史互动
- 只有在足够长的记忆背景下，才能真正测出 Agent 的人格一致性和认知-行为一致性

## 质量控制方法

### 问题分类框架

数据集质量问题分为两类：

**硬性问题（必须修正）**：
- 角色漂移：角色行为与设定不符
- 记忆错乱：记忆内容矛盾或逻辑错误
- 格式异常：JSON 格式错误、字段缺失等

**软性问题（可以优化）**：
- 轻微的言行不一
- 语气突兀
- 思维方式偏差

这个分类框架的价值在于：它让数据构建团队能够快速判断哪些问题必须修正，哪些可以酌情处理，提高了迭代效率。

### phase-8 复检发现的典型问题

1. **记忆载体异常**：context 和 content_full 内容不一致
2. **过度解释**：简单事件被赋予过多心理学意义（如做饭被油溅到→"强烈的自我设限和错误回避倾向"）
3. **视角混乱**：第一人称记忆混入第三人称描述
4. **内容高度相似**：同一角色的多条记忆内容几乎重复
5. **心理结论与内容矛盾**：结论与实际记忆内容不匹配
6. **年龄与场景不符**：17 岁角色出现在办公室项目会议场景

## 团队协作体会

### 第一次感受到协作压力

这个项目让我第一次真正感受到团队协作的压力。原因是：

1. **概念抽象且不固定**：数据集中的概念和指标比较抽象，且不是一开始就确定的，而是在讨论中逐步清晰的
2. **信息传递的脆弱性**：漏听一点或没有及时整理就会和团队脱节
3. **工作量巨大的琐碎细节**：角色屏蔽、格式检查、专家对接等，都是繁琐但关键的工作

### 养成的习惯

通过这个项目，我养成了两个重要习惯：

1. **及时整理**：每次会议或讨论后，立即整理笔记，确保概念和决策被记录下来
2. **工作留痕**：所有的工作都有文档记录，包括方案设计、问题发现、修改建议等

这两个习惯在后续的工作中一直受益。

## 专家标注规范的设计

### 核心原则

标注规范的核心原则是：**选最符合角色在当前场景下最可能实际做出的反应，不是选"最正确"或"最成熟"的**。

这个原则看似简单，但在实践中经常被违反。专家可能会倾向于选择"更成熟"或"更善良"的选项，而非"更符合角色"的选项。

### 判断顺序

设计了一个固定的判断顺序，避免专家在标注时遗漏关键步骤：

1. **是否废弃**：题目本身不可判或存在明显质量问题
2. **是否选 NONE**：题可标，但 A/B/C 都不够符合角色
3. **在 A/B/C 中选最优**：只在题可标且至少有一个选项可接受时进行
4. **填写置信度和理由**：必须说明角色在该选项中的行为逻辑，以及另外两个为什么不如它

### 选择标准优先级

1. **角色一致性**：是否符合角色核心人格设定、长期行为偏好、关系模式、防御机制、价值排序
2. **场景一致性**：是否符合当前触发强度
3. **行为可执行性**：是否是角色当下真实做得出来的事
4. **激活记忆一致性**：是否能从激活记忆中找到足够支撑

总原则：**先看"像不像这个角色"，再看"是不是一般人也会这样做"**。
