# PRD: 阶段 2 — Candidate Agent MVP（无记忆）

**状态**: ready-for-review
**所属阶段**: 阶段 2（Candidate Agent MVP）
**上游约束**: ADR-0001（静态优先）、ADR-0002（部署时供应商切换）、ADR-0004（渐进式披露 + tool-use）、FRONTEND_DESIGN.md、产品大纲 5.x、CONTEXT.md 术语、CURRENT_STATE.md 当前事实

## Problem Statement

阶段 1 已完成全部公开静态页面，访客现在可以独立浏览首页、在线简历和项目详情页。但 Candidate Agent 仍然只有首页 CTA 占位，没有真正的 `/agent` 页面，也没有 `POST /api/chat` 对话端点。

这导致站点虽然已经是一个完整的静态简历容器，但还缺少产品大纲中定义的“资料问答助手”主能力：访客不能直接询问项目细节、岗位匹配度、优势与不足，也不能粘贴 JD 获得基于现有资料的分析。

阶段 2 的目标是补上 **无记忆 Agent MVP**：先把问答主链路打通，让 Agent 能基于 `content/` 中的资料回答问题、按需读取文件、流式输出、并在失败时优雅降级。**短期记忆、D1 持久化、UUID 限频与全局限频不属于本阶段，统一留到阶段 3。**

## Solution

新建 `/agent` 页面与 `functions/api/chat.ts`，使用 React Island 承载聊天交互，用 Pages Functions 调 LLM API。主上下文仅包含 system prompt、answer-rules、profile 摘要与文件索引，LLM 通过 tool call 按需读取 `content/` 下的简历、项目详情页正文与 Agent 参考资料；后端处理最多 5 轮 tool-use 循环，并通过 SSE 将回答和中间状态流式返回前端。

本阶段只交付“可问、可查资料、可流式回答、可失败降级”的 Agent MVP，不接入短期记忆、不落 D1、不做限频、不做 admin 统计。这样既符合现有阶段拆分，也能把风险控制在最小可验证闭环内。

## User Stories

### Agent 页面与基础对话

1. 作为访客，我希望访问 `/agent` 能看到独立的 Candidate Agent 页面，这样我不必回首页 CTA 才能开始提问。
2. 作为访客，我希望页面清楚说明这是一个基于简历、项目文档和公开作品资料构建的资料问答助手，这样我知道它的边界。
3. 作为访客，我希望输入问题后能得到回答，这样我可以快速了解候选人的经历和项目。
4. 作为访客，我希望 Agent 跟随我的提问语言回答，这样中文问答和英文问答都自然。
5. 作为访客，我希望在发送前看到“提问内容可能被记录，请勿输入敏感信息”的提示，这样隐私边界清楚。
6. 作为访客，我希望当 Agent 服务失败时看到明确的降级提示，并被引导去看静态简历和项目页，这样页面不会变成死路。

### 预设问题与 JD 粘贴分析

7. 作为访客，我希望页面上有预设问题按钮（自我介绍、项目问答、岗位匹配、优势不足、面试问题），这样我可以快速开始。
8. 作为访客，我希望粘贴一段 JD 后能让 Agent 从现有资料出发分析匹配点、风险点和建议追问，这样我能快速判断候选人与岗位的相关性。
9. 作为访客，我希望 JD 分析仍然受“只根据资料回答”的边界约束，这样不会出现脱离资料的猜测。

### 资料读取与回答边界

10. 作为访客，我希望询问某个项目细节时，Agent 能按需查阅对应项目资料，而不是只靠一小段首页摘要回答。
11. 作为访客，我希望 Agent 在资料不足时明确说“无法确认”，这样我不会把猜测当事实。
12. 作为访客，我希望 Agent 不回答薪资承诺、面试安排、私人敏感信息等问题，这样它不会越界。
13. 作为开发者，我希望 Agent 读取的是 `content/` 里的既有资料，而不是额外维护一套知识库，这样维护成本最低。
14. 作为开发者，我希望 `refs/*.md` 只通过 Agent 问答间接使用，不生成公开路由，这样分层信息披露边界不被破坏。

### 流式交互与可维护性

15. 作为访客，我希望回答是流式出现的，而不是长时间无反馈后一次性跳出全文，这样等待体验更好。
16. 作为访客，我希望看到简短的中间状态提示（例如“正在查阅某个项目资料”），这样我知道 Agent 在做什么。
17. 作为开发者，我希望 tool-use 循环上限固定为 5 轮，这样成本和复杂度可控。
18. 作为开发者，我希望 DeepSeek 和 MiMo 通过同一抽象层接入，这样未来切换供应商不需要重写聊天主流程。

## Implementation Decisions

### 阶段范围

- **本阶段包含**：`/agent` 页面、React Island 聊天 UI、`POST /api/chat`、provider 抽象、tool-use 文件读取、流式 SSE、失败降级、隐私提示、预设问题、JD 粘贴分析。
- **本阶段明确不包含**：短期记忆、D1 持久化、UUID、限频、埋点、admin 能力。

### `/agent` 页面

- 新建独立页面 `/agent`，不再复用首页 CTA 作为唯一入口。
- 页面包含：标题说明、预设问题区、聊天消息区、单行提问输入框、发送按钮、JD 粘贴文本域、分析按钮、隐私提示。
- 交互由 React Island 承载，公开展示页仍保持 Astro 静态优先；只在 `/agent` 页面引入交互岛。
- 页面错误态遵循 `FRONTEND_DESIGN.md`：不使用 toast，不阻断浏览，直接在对话区域展示降级文案。

### `POST /api/chat`

- 新建 `functions/api/chat.ts`。
- 请求职责：接收当前提问（以及前端触发 JD 分析时拼接后的引导语），构造主上下文，请求当前生效供应商，处理 tool call，返回 SSE。
- 本阶段接口保持无记忆：每次请求只处理当前轮问题，不恢复历史上下文，不读写 D1。

### 主上下文组成（ADR-0004）

- `content/agent/system-prompt.md`
- `content/agent/answer-rules.md`
- `content/profile.json` 的摘要
- 文件索引：可供 Agent 选择的资料清单及一句话摘要

文件索引至少覆盖：
- `resume.json`
- 每个项目的 `index.md`（项目详情页正文）
- 每个项目 `refs/*.md`（Agent 参考资料）

### tool-use MVP

- 采用最小 `read_file` 风格工具：输入文件标识，返回对应文件完整内容。
- 后端负责校验可读范围，只允许读取白名单资料文件，不允许任意路径访问。
- LLM 可连续读取多个文件，但总循环上限为 5 轮；超限后强制基于已有内容收尾回答。

### 模型供应商抽象

- DeepSeek 与 MiMo 实现同一接口。
- 当前生效供应商由环境变量 `ACTIVE_PROVIDER` 决定，不做运行时切换 UI。
- 落地时先用最小 `read_file` 示例验证两家在 tools/function calling 响应格式上能被同一主流程消费。

### JD 粘贴分析

- JD 粘贴分析不是独立 API；复用 `POST /api/chat`。
- 前端负责把“请基于以下岗位描述分析匹配点、风险点和建议追问”之类的引导语与 JD 文本拼成一次普通提问。
- Agent 仍受 answer-rules 约束：只能依据现有资料分析，不做脱离资料的打分或承诺。

### 失败降级

- LLM API 失败时，前端显示：Agent 暂不可用，请查看静态简历和项目页。
- 不因 Agent 失败阻断 `/agent` 页面本身的访问。
- 本阶段不处理 D1 失败分支，因为尚未接入 D1。

### 导航与入口

- 阶段 2 完成后，站内 Agent 入口从首页 CTA 占位/`/#agent` 切换为真正的 `/agent` 页面。
- 首页 `AgentCTA` 的按钮目标应改为 `/agent`。

## Testing Decisions

好的测试只验证用户可感知行为和关键边界，不锁死内部实现。

### Seam 1：`/agent` 页面可访问性（E2E）

- `/agent` 返回 200
- 页面出现 Candidate Agent 标题、隐私提示、输入框、发送按钮、JD 文本域、预设问题按钮

### Seam 2：基础聊天流程（E2E / 集成）

- 发送普通问题后，页面出现流式或最终回答
- 预设问题按钮点击后能触发一次有效提问
- 粘贴 JD 并点击分析后能触发一次有效问答

### Seam 3：边界行为（集成）

- 询问项目细节时，Agent 能基于资料回答，不是空泛模板
- 询问资料外信息时，Agent 明确表示无法确认
- 询问薪资/私人敏感信息时，Agent 拒绝越界回答

### Seam 4：降级路径（集成）

- 模拟 LLM API 失败时，对话区显示降级提示，页面不崩

### Seam 5：tool-use 主流程（集成）

- 最小 `read_file` 工具在 DeepSeek 和 MiMo 下都能跑通至少一个真实文件读取例子
- 超过 5 轮时，服务端能强制收尾，不进入无限循环

### 不做的事

- 本阶段不验证短期记忆恢复
- 本阶段不验证 D1 入库
- 本阶段不验证限频
- 本阶段不引入 admin 相关测试

## Out of Scope

- 短期记忆（localStorage UUID + 24h）
- D1 对话持久化
- UUID 限频和全局限频
- 行为埋点 `POST /api/track`
- admin 面板与私有统计接口
- FAQ、多 Agent、多用户、长期记忆、RAG/向量检索
