# ADR-0002: 模型供应商切换采用部署时环境变量，不做 admin 运行时切换

## 状态

accepted

## 上下文

Candidate Agent 需要接入外部 LLM API，第一版同时兼容 DeepSeek 和 MiMo 两家供应商。需要决定"当前用哪家供应商"这个状态如何切换。

候选方案：

- **运行时切换**：两个供应商的 API key 都在环境变量里，admin 页面提供一个开关，切换状态存 KV 或 D1，代码运行时读取并取对应 key。
- **部署时切换**：同样两个 key 都在环境变量里，另加一个 `ACTIVE_PROVIDER` 环境变量决定当前用谁，切换 = 改环境变量 + 重新部署。

## 决策

采用**部署时切换**：两个供应商的 API key 通过 Cloudflare Secrets 注入，`ACTIVE_PROVIDER` 环境变量决定当前生效的供应商，切换需重新部署。

第一版不建设 admin 模型切换面板。

## 理由

1. **切换是低频运维操作**：只有两家供应商，实际切换场景是故障应急或效果对比，频率远低于"日常产品功能"，为它建带数据库写入的 admin UI 属于过度设计。
2. **符合产品大纲"低维护优先"与"第一版不建设复杂后台"**：大纲明确第一阶段无后台页面，第二阶段 admin 也只用于查看数据，不做管理系统。
3. **安全面最小**：API key 只在环境变量，不落库，无需加密管理。
4. **可演进**：未来若发现切换频率上升，可将"Active Provider 的决定方式"从部署时环境变量改为运行时 KV/D1，术语与抽象层不变。

## 代价

故障应急时无法做到秒级切换，需 3-5 分钟完成 `wrangler secret put` + 触发部署。对两家供应商的低频切换场景可接受。
