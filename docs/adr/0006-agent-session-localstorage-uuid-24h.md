# ADR-0006: Agent 会话上下文采用 localStorage UUID + 24 小时短期记忆

## 状态

accepted

## 上下文

Agent 需要支持单次会话内的多轮对话上下文（追问能指代前文），并进一步要求：同一访客一天内重开页面后仍可延续之前的对话，隔天清空。

候选方案：

- **无状态，每问独立**：每次请求只带当前问题。追问体验差。
- **有状态，会话存储**：用会话 ID 关联历史，存 D1/KV。体验好但需要服务端会话管理。
- **前端带历史，后端无状态**：前端把历史一起发。刷新页面后历史丢失，无法满足"一天内延续"。
- **localStorage UUID + 24h 短期记忆**：前端生成随机 UUID 存 localStorage 作为访客标识，后端用此 UUID 关联对话历史存 D1，24 小时后自动清理。

访客标识候选：

- IP 哈希：违背大纲"不存完整 IP"。
- Canvas/WebGL 硬件指纹：撞大纲"不采集设备指纹"红线，且部分浏览器抵抗，隐私合规风险。
- localStorage UUID：不碰 IP 和硬件指纹，最干净。

## 决策

采用 **localStorage UUID + 24 小时短期记忆**：

1. 前端首次访问生成随机 UUID 存 localStorage，每次 chat 请求带上。
2. 后端用此 UUID 作为会话 key，对话历史存 D1。
3. 同一 UUID 一天内的请求共享同一上下文，重开页面后仍可延续。
4. 超过 24 小时后，访客侧不再延续历史（前端视为新会话），但 D1 中的对话记录永久保留，不自动删除，供管理者下载分析。
5. 前端 UUID 可编码生成日期，隔天自动生成新 UUID，或由后端按时间判断该 UUID 的对话是否已超出 24h 展示窗口。

## 上下文恢复的 token 预算

恢复短期记忆时，从最近的消息向前累加 token，每个 UUID 每天限制在 100K token 预算内，超出部分丢弃。避免历史过长导致主上下文 + 历史超 LLM 窗口或成本失控。存储层仍完整保留所有消息（含 tool call 与 tool result），token 预算仅作用于恢复时的上下文重建。

## 理由

1. **满足"一天内延续"**：后端有状态存储，刷新页面不丢上下文。
2. **满足"隔天清空"**：24 小时 TTL + Cron 清理，数据不无限累积。
3. **隐私最干净**：不存 IP、不采集硬件指纹，localStorage UUID 是客户端随机标识，清缓存即重置，访客可控。
4. **不违背大纲**：长期记忆仍不做，24 小时短期记忆是对"暂不做长期记忆"的细化；localStorage UUID 不属于大纲禁止的"设备指纹"。

## 代价

- 换设备 / 清缓存 / 无痕模式会丢失上下文——对"一天内短期记忆"场景可接受。
- 需要后端会话存储（D1 表）和定时清理任务（Cron Trigger），比纯无状态复杂。

## 降级策略

D1 不可用时，Agent 自动降级为无记忆模式（每问独立，不持久化历史），并在前端给出轻微错误提示（如"记忆服务暂时不可用，本次对话不会保留上下文"）。Agent 本身仍可正常回答，符合大纲"失败可降级"原则。不做静默重试。
