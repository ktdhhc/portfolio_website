# ADR-0007: Agent 防滥用采用 UUID 限频 + 全局限频双层，不做 Origin 校验

## 状态

accepted

## 上下文

Agent 接口 `/api/chat` 调用外部 LLM API 产生成本，需要防滥用机制。

候选方案：

- **UUID 限频**：同一 localStorage UUID 每小时限 20 次。挡同站单点滥用，但攻击者每次生成新 UUID 可绕过。
- **全局限频**：所有请求每天累计 200 轮，超限全站降级提示"今日 Agent 已达上限"。保总成本上限。
- **Origin/Referer 校验**：拒绝非本站来源的请求。挡跨站脚本，但 Referer 可伪造。
- **同源 token**：页面加载时发短期 token，请求必须携带。最难伪造但最复杂。

## 决策

采用 **UUID 限频 + 全局限频双层**：

1. UUID 限频：同一 localStorage UUID 每小时限 20 次。
2. 全局限频：所有请求每天累计 200 轮，超限全站降级为"今日 Agent 已达上限，请查看静态简历"。
3. **不做 Origin 校验**，不做同源 token。

## 理由

1. **个人简历站访问量低、被针对性攻击概率低**——过度防御不符合"低维护"原则。
2. **全局限频封顶成本**——最坏情况是当天 200 轮被刷完、Agent 全天降级，成本可控，正常访客可看静态简历（符合大纲"失败可降级"）。
3. **可演进**——若未来真的遇到攻击，再加 Origin 校验或 Cloudflare WAF 规则，不影响现有架构。

## 代价

不做 Origin 校验意味着外部脚本可轻易打满 200 轮上限，导致当天 Agent 全天降级。这是被接受的已知风险——在当前访问量级别下，防御投入不划算，等遇到问题再补。

## 已知风险记录

若该站开始被针对性攻击，应优先补 Origin 校验（Pages Functions 检查 `Origin`/`Referer` 头），将跨站脚本挡在外层，让全局限频回归"挡总成本"的本职。
