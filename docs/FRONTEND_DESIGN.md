# FRONTEND_DESIGN

> 稳定设计约束文档 | 适用于初版及后续版本的前端实现

## 1. 文档目的

本文件用于统一本项目的前端视觉风格、页面结构和组件实现方式。目标是在“极简、稳定、低开发负担”的前提下，让设计保持一致。

本文件为稳定约束，仅当产品定位发生根本变化或用户主动要求时才可修订；其余小功能迭代不得违背上述规则。

## 2. 前端定位

本项目前端的首要目标是：

作为一份**稳定、可访问、可维护的在线简历容器**，面向 HR、面试官和合作方，快速传达候选人的背景、能力和项目价值。Agent 页面是增强层，不是主体；即使 Agent 不可用，静态页面必须完整承担简历展示功能。

## 3. 总体设计原则

- **稳定优先**：公开页面尽量静态化，避免因为后端、模型 API 或数据库异常导致简历主体不可访问。
- **低维护优先**：内容更新通过 Markdown / JSON 配置文件完成，不建设复杂后台。
- **留白优先，宁缺毋滥**：大量留白比堆砌信息更重要。Section 间距 8rem 起，内容区最大宽度 800px，不撑满屏幕。
- **温暖科技风**：拒绝极客黑和赛博霓虹。用暖白背景 + 深暖灰文字 + 暖棕 accent，营造“有温度但不喧闹”的质感。
- **失败可降级**：Agent 调用失败时，页面应提示访客查看静态简历和项目页。数据统计失败时，不应影响页面正常浏览。

## 4. 视觉基调

### 风格关键词

- 温暖（Warm）
- 克制（Restrained）
- 结构化（Structured）
- 可信（Trustworthy）

### 页面气质

页面应让人感觉：

> 这个人不是在炫技，而是在认真思考 AI 产品怎样不胡说、怎样可用、怎样被维护。

避免：粒子特效、3D 球、赛博霓虹、AI 光效、过度动画、手绘幼稚感。

## 5. 颜色规范

### 基础色

| Token | 值 | 用途 |
|-------|-----|------|
| `--bg` | `#faf8f5` | 页面主背景，暖白色 |
| `--bg-elevated` | `#ffffff` | 卡片/浮层背景 |
| `--bg-muted` | `#f5f0e8` | 次要背景、hover 态 |
| `--fg` | `#1f2329` | 主文字，深暖灰 |
| `--fg-secondary` | `#5c5652` | 次要文字、描述 |
| `--fg-muted` | `#9a9590` | 辅助文字、时间戳 |
| `--border` | `#e8e0d4` | 边框、分隔线 |
| `--border-hover` | `#d4ccc0` | hover 态边框 |

### 强调色

| Token | 值 | 用途 |
|-------|-----|------|
| `--accent` | `#d4a574` | 标签边框、装饰线、脉冲点 |
| `--accent-dark` | `#b8895a` | 标题高亮、强调文字 |
| `--accent-bg` | `#fef6ee` | badge 背景、CTA 区块背景 |

### 状态色

- 成功：`#6dbf7a`（仅用于 Hero 状态点）
- 错误/警告：不使用高饱和红色，用文字提示替代
- 禁用：`--fg-muted`

## 6. 字体与排版

- **字体栈**：`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "PingFang SC", "Noto Sans SC", sans-serif`
- **原则**：全程使用系统字体，不引入外部字体文件（减少请求、降低维护）。
- **字号层级**：
  - Hero 标题：`3.5rem / font-weight: 700 / letter-spacing: -0.03em`
  - Section 标题：`1.75rem / font-weight: 700 / letter-spacing: -0.02em`
  - 卡片标题：`1.15rem / font-weight: 600`
  - 正文：`0.95rem / line-height: 1.7`
  - 辅助文字：`0.85rem`
  - 标签（Tag）：`0.85rem`
- **行高**：正文 `1.7`，标题 `1.1 - 1.25`

## 7. 间距与圆角

### 间距

- 页面容器最大宽度：`800px`，水平居中
- 容器内边距：`0 2rem`（移动端 `0 1.5rem`）
- Section 间距：`8rem`（约 128px）—— 宁大勿小
- 卡片内边距：`2rem - 2.5rem`
- 组件间间隙：`1rem - 1.5rem`

### 圆角

| 元素 | 圆角 |
|------|------|
| 卡片 | `16px` |
| 按钮 | `8px` |
| 标签/Link | `6px` |
| Badge/Pill | `100px` |
| Agent CTA | `20px` |

## 8. 页面布局规范

### 通用页面结构

每个页面遵循统一结构：

```
[固定导航栏]
  └── 左侧：姓名/Logo（链接回首页）
  └── 右侧：下拉菜单导航
        ├── "简历 ▾" → 展开：教育 / 经历 / 技能 / PDF 下载（若 PDF 缺失则显示待补充）
        ├── "项目 ▾" → hover 展开：各项目名 + 查看全部
        └── "Agent" → 链接到首页 Agent CTA（阶段 2 后指向 /agent）

[Hero 区域] — 仅首页
  └── 状态 Badge
  └── 大标题（含 Accent 高亮词）
  └── 一句话定位
  └── CTA 按钮组

[Section × N]

[Agent CTA] — 仅首页

[Footer]
  └── 外部链接（GitHub、产品主页、Email）
  └── 版权信息
```

导航栏统一使用下拉模式：桌面端鼠标靠近自动展开；触屏和键盘通过按钮点击 / Enter / Space 展开，点击外部或按 `Esc` 收起。实现可带极小内联脚本，但不引入额外前端框架。所有页面交互一致，不再区分首页锚点模式和页面链接模式。

### 布局建议

- **Hero 居中**：标题、描述、按钮全部水平居中，最大宽度 560px
- **内容左对齐或居中**：教育经历用左对齐列表；技能标签用居中的云状排列；项目卡片用单列网格
- **单栏为主**：内容区以单列为主，避免多栏造成的阅读跳跃。仅在导航等少数场景使用 flex 横向布局。

## 9. 组件最小集合

不要在第一版扩展复杂组件库。以下组件足以覆盖 MVP：

- **Nav**：固定顶部，backdrop-filter blur，底部细边框。桌面 hover 自动展开下拉，触屏/键盘可点击展开；使用 `button` 语义，不再使用纯锚点链接
- **SectionHeader**：英文小写标签（`section-tag`）+ 中文标题（`section-title`），居中
- **Badge**：圆角 pill，带左侧脉冲点，用于 Hero 状态提示
- **Button**：`btn-primary`（深色填充）和 `btn-secondary`（边框），圆角 8px
- **Card**：圆角 16px，1px 边框，白色背景，hover 时边框加深 + 极淡阴影
- **Tag/Pill**：圆角 100px，用于技能标签。高亮项用 `--accent-bg` 背景 + `--accent` 边框
- **Link**：圆角 6px，1px 边框，hover 时边框和文字变色
- **Divider**：1px `--border`，用于列表项分隔和区块分隔

## 10. 关键页面规范

### 首页（/）

- Hero 区域：状态 Badge + 大标题 + 定位描述 + CTA（下载简历 + Agent 对话）
- 代表项目：1-2 张 featured 项目卡片 + "查看全部项目"链接
- Agent CTA：暖色背景区块，引导访客与 Agent 对话
- 首页定位为"精选橱窗"，不再铺开教育/技能/经历等完整简历内容（那些在 /resume 页面）

### 在线简历页（/resume）

- 承载完整简历内容
- 必须在没有 Agent 的情况下也能独立成立
- 包含：教育、工作/实习/项目经历、技能栈、研究方向、代表项目、PDF 下载入口（若 PDF 缺失则显示待补充文案而不是坏链接）

### 项目列表页（/projects）

- 展示代表项目卡片
- 每张卡片：项目名称、一句话说明、项目类型、个人角色、核心能力标签、项目详情入口、GitHub/Demo/文档链接

### 项目详情页（/projects/[project]）

- 统一结构：项目背景 → 解决的问题 → 我的职责 → 核心设计 → 技术或工具 → 产出结果 → 难点与复盘 → 可验证材料 → 可追问问题
- 正文采用九段式叙述，公开可访问，构建时生成静态页面

### Candidate Agent 页面（/agent）

- 基于候选人资料构建的问答助手
- 页面顶部提示：提问内容可能会被记录，请勿输入敏感信息
- Agent 失败时，提示访客查看静态简历和项目页
- 预设问题按钮：自我介绍、项目问答、岗位匹配、优势不足、面试问题、JD 分析
- 输入框附近显示隐私提示

### 后台页面（/admin）

- 第二阶段才建设
- 受保护，仅候选人本人可访问
- 展示：访问量、热门页面、简历下载次数、项目点击排行、Agent 高频问题、失败记录、JD 分析次数
- 提供提问记录导出与手动清理能力

## 11. 状态展示规范

- **加载态**：不使用全屏 loading spinner。按钮使用 `opacity` 变化或禁用态提示。
- **空态**：文字直接说明“暂无数据”或“暂无记录”，不使用插图。
- **错误态**：Agent 调用失败时，在对话区域显示降级提示：“Agent 服务暂时不可用，请查看静态简历和项目页了解更多。” 不阻断页面浏览。
- **成功态**：不使用 toast。Agent 回答直接显示在对话流中；行为追踪静默上报，不给用户反馈。
- **禁用态**：按钮 `opacity: 0.5` + `cursor: not-allowed`。

## 12. 表格设计规则

第一版不使用表格。如需展示结构化数据，使用卡片列表或标签云替代。

## 13. 表单设计规则

- **Agent 输入框**：单行文本输入，底部放置发送按钮。输入框下方常驻隐私提示文案。
- **JD 粘贴分析**：多行文本域，支持粘贴 JD 文本，点击分析后显示结果。
- **表单校验**：前端只做非空校验，错误提示用红色文字（`#b8895a` 的深色变体，或直接使用 `--fg-secondary` + 前缀符号 ⚠️）。

## 14. 审查与差异展示

- 不使用 diff 组件或对比视图。
- 如需展示变化，用文字描述替代。

## 15. 交互与动效

### 原则

- **克制、明确、不炫技**：hover 只有颜色/透明度变化，无位移、无缩放、无弹跳。
- **过渡时间统一 0.2s**：所有 hover、focus 过渡使用 `transition: all 0.2s ease`。
- **仅动画 opacity**：脉冲状态点使用 `animation: pulse 2s ease-in-out infinite`，这是唯一允许的循环动画。

### 具体规则

| 元素 | 交互 |
|------|------|
| 导航链接 | hover 文字色从 `--fg-secondary` 变为 `--fg` |
| 按钮 primary | hover `opacity: 0.85` |
| 按钮 secondary | hover 边框和文字色加深 |
| 卡片 | hover 边框加深 + `box-shadow: 0 4px 20px rgba(31, 35, 41, 0.06)` |
| 标签 | hover 边框变为 `--accent`，文字变 `--fg` |
| 链接 | hover 边框和文字色加深 |

### 禁止

- 禁止滚动触发动画（scroll-triggered animations）
- 禁止 3D 变换、透视、粒子
- 禁止页面加载动画/ splash screen
- 禁止模态框弹入弹出动画（如需模态框，直接淡入 `opacity`）

## 16. 响应式要求

### 断点

- 桌面：> 640px
- 移动端：<= 640px

### 移动端适配

- Hero 标题缩小至 `2.25rem`
- 导航下拉菜单保留（tap / 点击按钮展开），间距适当缩小
- 简介元信息从横向排列改为纵向堆叠
- 实习/项目卡片的 header 从横向 flex 改为纵向堆叠
- 内容容器 padding 缩小至 `0 1.5rem`

## 17. 开发减负规则

- 首版不引入不必要的复杂组件系统（如 shadcn/ui、Ant Design、Material UI）。
- 优先复用少量稳定组件（Card、Badge、Button、Tag、SectionHeader）。
- 不为偶然页面创建过多特殊样式。
- 可用纯 CSS 解决的问题，不额外引入重型依赖。
- 不引入字体图标库（如 FontAwesome），如需图标使用内联 SVG 或系统 emoji。
- 不引入前端路由库（如 React Router），如使用多页方案，用文件系统路由。
- 图片资源优先使用外部链接（GitHub avatar、项目截图托管），减少仓库体积。

## 18. 实现建议

### 技术栈

- **静态站点生成器**：Astro / Vite + 纯 HTML，或 Next.js Static Export
- **样式**：原生 CSS 变量（如 demo 中的 `:root` 方案）或 Tailwind CSS
- **部署**：Cloudflare Pages（稳定、CDN、免费额度充足）
- **内容管理**：Markdown / JSON 文件放在 `content/` 目录，构建时读取

### 内容组织

```text
content/
  profile.md
  resume.json
  faq.md
  projects/
    aindexer.md
    agent-memory.md
  agent/
    system-prompt.md
    answer-rules.md
```

### 字体

- 全程使用系统字体，不加载外部字体文件。
- 如需要手写体感，可在标题处使用系统自带的手写体 fallback（如 `"PingFang SC", "Noto Sans SC"`），但不做强制要求。

### 性能

- 首屏关键 CSS 内联（如 demo 中的 `<style>` 方案），避免阻塞渲染的外部 CSS 请求。
- 图片懒加载，使用现代格式（WebP/AVIF）。
- 不引入大型 JS 框架（如 React/Vue）用于纯展示页面，除非 Agent 页面需要交互状态管理。

## 19. 设计验收标准

- [ ] 页面是否符合“温暖科技风”定位（暖白背景、深暖灰文字、暖棕 accent）
- [ ] 留白是否充分（Section 间距 >= 8rem，内容不拥挤）
- [ ] 组件、色彩、间距、圆角是否一致
- [ ] 是否避免了无意义的装饰（无粒子、无 3D、无赛博霓虹）
- [ ] hover/交互是否克制（仅颜色/透明度变化，0.2s 过渡）
- [ ] Agent 失败时是否有降级提示，不阻断页面浏览
- [ ] 移动端是否可用（标题缩小、卡片纵向堆叠、导航简化）
- [ ] 是否降低了后续开发维护成本（组件复用、CSS 变量、内容 Markdown 化）
- [ ] 是否没有违背本文件中的稳定约束
