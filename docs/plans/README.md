# docs/plans

本目录用于存放项目方案和重要演进说明，不是日常记录或临时调试材料的归档处。

## 适合放入

- 项目初版实施方案
- feature 设计方案
- 核心流程改版方案
- 数据结构改版方案
- 前端大调整方案
- Agent prompt / workflow 重大调整方案
- 架构取舍说明（若未被 ADR 覆盖）

## 不适合放入

- 日常工作记录
- 每次小修改的说明
- 临时排障过程
- 与当前项目已无关的废弃草案
- 已经被 `docs/CURRENT_STATE.md` 覆盖的当前事实
- 已记录在 `docs/adr/` 中的架构决策（ADR 是 ADR，plan 是 plan，不重复）

## 命名规则

- 使用清晰、语义化、面向主题的英文 kebab-case 文件名。
- 不默认用日期开头，除非项目强依赖版本或阶段时间线。
- 文件名优先表达内容主题。

## 当前文件

```text
initial-implementation-plan.md   # 初版实施方案，覆盖阶段 0-5 的工程落地路线
```

## 与 ADR 的关系

`docs/adr/` 记录的是**为什么做某个架构决策**（上下文、决策、理由）。
`docs/plans/` 记录的是**怎么落地**（阶段拆分、实现步骤、验证方式）。

两者互补但不重复。若某项 plan 落地后产生了新的难逆决策，应在 `docs/adr/` 新增 ADR 记录决策本身，plan 中只引用 ADR 编号。
